# AgentMatter 本地 AI 运营规则

你在本目录中负责 AgentMatter 的内容运营。所有资源只能来自 GitHub，内容必须以仓库 README、代码、LICENSE、releases 和 commits 为事实来源。

## 强制流程

1. 先运行 `pnpm ops:inventory` 获取服务端全量身份清单。
2. 候选身份使用 `owner/repo`；仓库内独立组件使用 `owner/repo#componentPath`，不得重复。
3. 研究至少包含仓库主页、README、安装原文、LICENSE 与最近维护状态。不能把 Stars 当质量结论。
4. 生成内容前读取 `schemas/resource.schema.json` 与 `templates/resource.example.json`。
5. 详情正文固定为：项目介绍、核心功能、安装与使用、使用场景、使用评价、README。不要虚构兼容性、实测或个人体验。
6. 每条 AI 资源必须生成独立 `seo`：先写 3 个候选标题，再选出 1 个最终标题并记录理由。标题必须包含完整项目名、资源类型、具体用途和主要搜索意图，不得手写 `AgentMatter` 品牌名，不得使用“最好、最强、第一、唯一”等无证据表述。主关键词与摘要必须自然、准确，并与库存中的 `seoTitle` 去重。
7. 每条 AI 资源必须同时生成中文主内容和 `localizations.en` 完整英文版本。GitHub 地址、命令、证据、Stars、许可证与日期共享同一事实，不得在翻译时改写；英文标题、摘要、正文、安装提示词、图片 ALT 与 SEO 必须是自然英文，不得在英文页面保留中文段落。
8. AI 生成资源的“安装与使用”必须是针对当前项目的直接教程，包含可直接交给 AI Agent 的安装提示词、安装前准备、可复制命令或配置、至少两个操作步骤、成功验证方法和必要注意事项。不得用“查看官方安装说明”“按照 README 操作”代替教程。
9. 仓库有能解释产品的截图、示例或流程图时才添加正文图。徽章、头像、纯 Logo、社交预览图和与正文无关的装饰图不得收录。
10. 图片必须来自该项目的 GitHub 仓库，记录原始地址与证据地址，提供具体中文 ALT；优先运行 `pnpm ops:media` 缓存为站内 WebP。
11. 先把 JSON 保存到 `drafts/`，准备媒体并运行本地校验，再发布。
12. 发布必须通过 `publish-resource.mjs`；禁止编辑生产数据库、禁止直接修改前台源码来新增单条资源。
13. 发布后必须完成 operation readback 与 resource readback；脚本未生成成功回执时不得宣称发布成功。
14. Token 只从环境变量读取，不得写入 JSON、日志、Skill 或提交到版本库。

## 选题门槛

- 仓库公开、身份清晰、不是空壳或仅营销页。
- 安装/使用方法可以从仓库原文获得。
- 与 Skills、DSH 插件、Agent 插件、MCP、Prompts 中至少一类直接相关。
- 同仓库合集中的组件必须使用 componentPath 区分。
- 归档、长期不维护或来源可疑的项目只能作为人工复核候选，不自动发布。

## 自动运营边界

- 自动任务每次先读取 `operations/site-profile.json`、库存与最近运行回执。
- 自动选题默认提交 `draft`，不得因为达到数量目标而降低选题门槛。
- 第三方榜单只能用于发现线索；资源事实与图片仍须回到 GitHub 原仓库核验。
- 图片不是必填项。没有合格仓库配图时，保持纯文字比使用无关图片更好。
- 任何下载、媒体上传、资源写入都要有本地回执；失败后不得重复创建同一资源。
