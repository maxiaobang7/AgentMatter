# AgentMatter 后台内容管理优化设计

## 目标

把能力领域从源码常量升级为可在后台维护的数据，补齐资源转草稿与可恢复删除能力，并把用户投稿审核从仪表盘底部迁移为独立页面。

## 方案选择

能力领域采用“数据库词库加静态默认值”方案。数据库配置正常时，前台和后台读取 `taxonomy_topics`；未配置数据库的本地静态模式继续使用 `CATEGORY_TAXONOMY`。迁移会把当前五个分类的全部能力领域写入数据库，因此升级不会改变现有筛选结果。标签 slug 创建后保持稳定，编辑只修改中英文名称、关键词和顺序。删除采用停用，仍被资源引用时拒绝停用并显示引用数量。

资源删除采用软删除。管理员点击“归档删除”后，资源状态变为 `archived`，前台不再返回该资源，版本和审计记录继续保留。转为草稿会把已发布资源切换为 `draft`，取消前台可见性，并保留当前内容作为可重新发布的草稿。两项操作都需要确认并写入 operations 与 audit_logs。

用户投稿独立为 `/admin/submissions`。仪表盘只保留待处理数量和入口，不再渲染整张投稿表。独立页面提供状态筛选、总数卡片、GitHub 地址、分类与组件路径、兼容平台、备注和审核状态。

## 页面结构

- `/admin` 作为运营概览，顶部固定显示“资源队列、能力领域、用户投稿”导航。
- `/admin/taxonomy` 按五个资源分类切换，显示启用和停用标签，支持新增、编辑、排序、停用和恢复。
- `/admin/submissions` 独立审核投稿，默认把新提交和审核中排在前面，并支持按状态筛选。
- `/admin/resources/[id]` 增加资源状态操作区，发布内容可转为草稿，任意非归档资源可归档删除。

## 数据与错误处理

- 新增 `taxonomy_topics` 表，唯一键为 `category + slug`，带 `active` 与 `sort_order`。
- 新标签使用小写连字符 slug，中英文名称必填；重复 slug 返回 409。
- 停用标签前扫描资源的正式与待审核 JSON；存在引用时返回 409，并带引用数量。
- 资源状态操作使用事务、幂等 operationId、审计日志和缓存刷新。
- 所有后台变更继续使用管理员会话和来源校验，不新增公开写接口。

## 验证

- 单元测试覆盖词库合并、标签输入校验、资源状态转换规则。
- API 路由测试覆盖未登录、非法输入和正常请求。
- 执行 Vitest、ESLint、TypeScript 和 Next.js 生产构建。
- 本地数据库可用时执行迁移并在浏览器验证三个后台页面和状态操作确认框。
