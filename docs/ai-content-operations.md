# AgentMatter AI 全自动内容运营方案

AgentMatter 使用“本地 Codex 运营内核 + 服务器内容接口”的结构。本地 Agent 负责发现、研究、写作、配图和判断；服务器负责认证、校验、媒体处理、存储、审计、版本和展示。服务器不保存模型密钥，也不负责生成文章。

## 每次运行的完整流程

1. 读取 `operations/site-profile.json`、运营规则、Schema 和模板。
2. 调用库存接口，盘点已发布、草稿和未发布资源，按 `owner/repo#componentPath` 去重。
3. 只从 GitHub 发现候选，第三方榜单最多作为线索。
4. 对候选按相关性、文档与安装、维护、社区认可、内容空缺、许可证和证据质量评分。低于 75 分不生成。
5. 读取仓库主页、README、安装原文、LICENSE、最近 commits 或 releases，并记录真正使用的来源。
6. 检查 README、`assets/`、`docs/` 和示例目录。只有截图、示例或流程图能解释项目时才选图，最多 3 张。
7. 生成严格资源 JSON。详情正文包含项目介绍、核心功能、安装与使用、使用场景、使用评价和 README；安装区必须根据当前项目生成可直接交给 AI Agent 的安装提示词，并整理准备条件、可复制命令或配置、操作步骤、成功验证和注意事项，不能只让用户去看官方文档。
8. 有图时运行 `pnpm ops:media <draft>`。服务器验证图片、转 WebP、保存内容寻址文件并返回媒体记录；本地脚本完成媒体读回。
9. 运行 `pnpm ops:validate <draft>`。
10. 无人值守任务使用 `draft`。人工明确要求发布具体资源时才使用 `publish` 或 `update`。
11. 发布脚本必须完成 operation 和 resource 双重读回并保存回执。

## 图片选择规则

正文图解决的是“仅靠文字不容易理解”的问题。合格图片通常是产品界面、输出示例、工作流图、功能对比或项目公开样例。徽章、作者头像、纯 Logo、仓库社交预览图和没有说明作用的装饰图不进入正文。

每张图必须具备 GitHub 原始地址、仓库证据地址、中文 ALT、可选图注、类别、插入位置和真实尺寸。图片缺失不是质量错误。没有合格图片时保持纯文字。

## 自动任务安全边界

- 定时任务默认每天最多生成 1 条草稿。
- 没有达到选题门槛时允许当天跳过。
- 任何安装、兼容性或功能实测结论都需要实际验证；只读仓库时标记为未验证。
- 写入前执行全状态去重，写入后检查稳定身份、状态、版本和内容哈希。
- 媒体上传与资源写入分别保存回执，网络重试不得创建重复资源或重复图片。
- 自动任务不执行下线、回滚或正式发布，除非用户明确授权具体目标。

## 建议的无人值守任务提示词

```text
在 AgentMatter 项目中执行一次 GitHub 资源草稿任务。完整读取 operations/AGENTS.md、operations/site-profile.json 和 operations/skills/agentmatter-publisher/SKILL.md。先获取全量库存并去重，再从 GitHub 选择一个与 Skills、DSH 插件、通用 Agent 插件、MCP 或 Prompts 直接相关的高质量候选。候选评分低于 75 分或证据不足时停止，不为了完成数量强行生成。

核对仓库、README、安装原文、LICENSE 和维护状态。按项目介绍、核心功能、安装与使用、使用场景、使用评价、README 生成中文内容，不虚构亲测。安装区要把仓库原文整理为准备条件、可复制命令或配置、至少两个操作步骤、成功验证方法和注意事项，不得用“查看官方安装说明”代替教程。检查仓库是否有能解释产品的截图、示例或流程图；有则最多选择 3 张，排除徽章、头像、纯 Logo 和装饰图，运行 ops:media 缓存为站内 WebP。完成本地与服务端校验后只提交 draft，最后核对媒体回执、operation readback、resource readback 和稳定身份唯一性。
```

该提示词是任务入口，真正的规则以项目内运营文件为准。这样可以更新一次规则后让所有后续自动任务同步生效。
